# View in AR Implementation Plan

**Goal:** A "View in AR" button in the tools panel that puts the open model in the room at real size on an iPhone, iPad or Android phone, and is not there on a desktop.

**Architecture:** Detection (`utils/viewInAr.js`) and state (`composables/useViewInAR.js`) live in the App chunk; what a press does (`ar/flow.js`, `ar/limits.js`, `ar/quickLook.js`, `ar/session.js`) is loaded by the first press. iOS writes a USDZ in metres (`utils/usdz.js`, shared with the USDZ download) and opens it through an `<a rel="ar">`; Android runs a WebXR `immersive-ar` session with hit-test over the viewer's own scene.

**Spec:** `docs/superpowers/specs/2026-11-13-view-in-ar-design.md`

## Global Constraints

- Nextcloud 31–35. Frontend only; no PHP.
- Every string through `t('threedviewer', …)`; `node scripts/check-i18n.mjs --sync-en` after adding strings.
- The VR button and `useWebXR` are untouched.
- The App chunk's budget in `scripts/check-bundle-size.mjs` is the limit; AR code beyond detection and the button is dynamically imported.
- Commits: conventional types, no Co-Authored-By. CHANGELOG under `[Unreleased]`, README Key Features bullet.

## Review Focus

1. **The scene is borrowed, not owned.** Everything `startArSession` changes (background, fog, visibility of every other child, scale, position, rotation, the model's own visibility, the animation loop, the reference space type) is put back on `end`, including when the session fails to come up. Pinned by `session.test.js` ("when the session ends", "ends the session and puts the scene back when it fails to come up").
2. **A tap on the page's own controls must not place the model.** `beforexrselect` is cancelled on the overlay.
3. **Real size.** 10 mm in an STL is a centimetre in both ways, 2 m in a glTF is 2 m. Pinned in Jest (USDZ read back; scene box measured after a tap) and in Playwright (the real blob).
4. **A phone that cannot take the model.** Refused past the limits; an out-of-memory write ends in a message and a working button.
